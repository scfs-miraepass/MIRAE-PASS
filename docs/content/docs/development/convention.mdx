## 코드 컨벤션

### 백엔드

- **포매터·린터**: Ruff를 사용하며 한 줄은 120자까지입니다.
- **비동기**: DB 쿼리, Redis 호출, 외부 요청 등 모든 I/O는 `async`/`await`로 작성합니다.
- **쿼리**: SQLAlchemy 2.0 스타일(`select`, `insert`, `update`)을 사용합니다.
- **의존성 주입**: DB 세션과 로그인 정보는 `SessionDep`, `LoginDep`으로 주입받습니다.
- **응답 형식**: 정상 응답은 항상 `ResponseModel[T](success=True, data=...)`로 감싸서 반환합니다. 실패는 `HTTPException`을 던지면 전역 핸들러가 `ErrorResponse`로 바꿔줍니다.
- **타입 힌트**: 모든 매개변수와 반환값에 타입 힌트를 붙이고, 복잡한 로직에는 한국어 주석을 남깁니다.

#### 새 API 추가하기

1. `app/router/endpoints/{도메인}.py`에 `APIRouter(prefix="/{도메인}", tags=["{도메인}"])`로 라우터를 만듭니다.
2. `app/router/__init__.py`에서 `include_router`로 등록합니다.
3. 로직이 길어지면 `app/core/service/{도메인}.py`에 `ServiceCore[모델]`을 상속한 클래스를 만들고, `app/core/service/__init__.py`의 `__all__`과 `ServiceClient`의 조회 메서드에 추가합니다.
4. 모델을 바꿨다면 마이그레이션을 생성합니다.
5. 백엔드를 실행한 상태에서 `yarn sdk-gen`으로 SDK를 다시 만듭니다.

<Callout type="info">
    더 자세한 백엔드 규칙은 `server/DEVELOPMENT_GUIDE.md`를 참고하세요.
</Callout>

### 프론트엔드

- **API 호출**: 직접 URL을 적지 않고 생성된 SDK(`$API`)를 사용합니다. 개발 환경에서는 `/api/**` 요청이 `localhost:8000`으로 프록시됩니다.
- **컴포넌트 배치**: `components/` 아래에 화면(도메인)별 폴더를 만들어 둡니다. Nuxt 자동 import 규칙에 따라 `components/karaoke/list/card.vue`는 `<KaraokeListCard />`로 사용합니다.
- **인증·권한**: 페이지별 권한 검사는 `middleware/*.global.ts`와 `utils/permission.ts`에서 처리합니다.
- **타입 검사**: `strict` 모드입니다. 커밋 전에 `yarn typecheck:client`, `yarn typecheck:admin`이 통과해야 합니다.

### 커밋 전 검사

`yarn install` 시 pre-commit 훅이 함께 설치됩니다. 커밋할 때 바뀐 파일에 따라 다음 검사가 자동으로 실행됩니다.

| 대상 | 검사 |
| --- | --- |
| `server/` | `ruff check --fix`, `ruff format` |
| `client/` | `yarn typecheck:client` |
| `admin/` | `yarn typecheck:admin` |

전체를 한 번에 검사하려면 `yarn typecheck`를 실행합니다.

## Git 컨벤션

### 브랜치

| 브랜치 | 용도 |
| --- | --- |
| `master` | 정식 릴리스. 푸시되면 버전이 올라가고 Docker 이미지가 배포됩니다. |
| `dev` | 개발 통합 브랜치. 푸시되면 `x.y.z-dev.n` 프리릴리스가 만들어집니다. |
| `feat/*`, `fix/*`, `docs/*` | 작업 브랜치. `dev`로 PR을 보냅니다. |

### 커밋 메시지

[Conventional Commits](https://www.conventionalcommits.org/ko/) 형식을 따르며, 설명은 한국어로 씁니다.

```text
<type>(<scope>): <설명>
```

```text
feat(client): 노래방 파티 초대 화면 추가
fix(server): stamp iso포멧에 맞지 않는 문제 해결
docs(docs): 개발 환경 구성 문서 추가
```

| type | 의미 | 버전 변화 |
| --- | --- | --- |
| `feat` | 새 기능 | minor (`1.13.0` → `1.14.0`) |
| `fix` | 버그 수정 | patch (`1.14.0` → `1.14.1`) |
| `docs` | 문서 | 없음 |
| `ci` | 워크플로 변경 | 없음 |
| `chore` | 그 밖의 잡일 | 없음 |

scope에는 바뀐 영역을 적습니다: `server`, `client`, `admin`, `sdk`, `docs`.

<Callout type="warning">
    버전과 `CHANGELOG.md`는 semantic-release가 커밋 메시지를 읽어 자동으로 관리합니다. `package.json`, `pyproject.toml`의 버전을 직접 수정하지 마세요.
</Callout>
