# AI 활용 가이드
이 문서에서는 생성형 인공지능을 미래패스 개발에 사용하는 경우, 생성형 인공지능의 사용 가이드라인을 설명합니다.

## 정의
인공지능과 사람 작업자를 철저하게 구분해야 합니다.<br />
본 문서에서는 생성형 인공지능을 '인공지능 작업자' 라고 하며, 그 인공지능을 사용하는 사람을 '사람 작업자' 라고 합니다.

## 공통 규칙 및 동작
인공지능 작업자 및 사람 작업자 모두가 지켜야 할 규칙 및 동작에 대해 설명합니다.
- [코드 컨벤션](/docs/development/convention#코드-컨벤션)을 반드시 지켜야 합니다.
- 인공지능 작업자와 사람 작업자의 의사소통은 수직 관계가 아닌 수평적인 관계이며, 인공지능 작업자 또한 사람 작업자에게 제안, 질문, 지적 등의 행동을 할 수 있습니다.
- 의견이 다른 경우 사람 작업자가 최종 결정하며, 인공지능 작업자는 그 결정에 따릅니다.
- 머지된 코드의 책임은 해당 PR을 머지한 사람 작업자에게 있습니다.

### 보안 및 데이터 [#security]
인공지능에 전달되는 모든 내용(프롬프트, 첨부 파일, 인공지능 작업자가 읽는 파일 등)에 아래 사항을 넣지 않습니다.

| 분류 | 항목 |
| --- | --- |
| 비밀값 | `.env` 파일, DB·Redis 비밀번호, API 키, 토큰, 암호화 키 등 |
| 개인정보 | 학생·교직원의 실제 이름, 학번, 연락처, 포인트 내역 등 |

- 인공지능 작업자는 `.env` 파일을 읽지 않습니다. 설정 구조가 필요한 경우 `example.env`를 참고합니다.
- 디버깅 등으로 실제 데이터가 필요해 보이는 경우, 구조만 같은 가짜 데이터를 만들어 사용합니다. 실제 데이터는 마스킹을 하더라도 넣지 않습니다.
- 인공지능 작업자는 로컬 개발 환경(로컬 DB·Redis·서버)만 사용합니다. 운영·개발 서버와 운영 DB에는 접속하지 않습니다.

## 인공지능 작업자

### 판단 범위 [#ai-판단범위]
인공지능 작업자가 작업 중 판단이 필요한 경우, 아래 기준에 따라 **먼저 묻거나** **PR에 기록하고 진행**합니다.

#### 먼저 묻기
아래 사항은 진행하기 전에 반드시 사람 작업자에게 먼저 묻고, 답을 받은 후 진행합니다.<br />
명령 실행의 경우 무엇을 왜 실행하는지 설명하고 승인을 받습니다.

| 분류 | 항목 |
| --- | --- |
| 의존성 | 라이브러리 추가, 의존성 버전 업그레이드 |
| 데이터 | DB 스키마 변경, 마이그레이션 생성 |
| API | 엔드포인트 추가·삭제, 요청·응답 형태 변경 |
| 보안 | 인증·세션·권한 로직 변경 |
| 범위 | 기존 코드·파일 삭제, 요청 범위 밖의 리팩터링 (구조 개선, 이름 변경, 파일 이동 등) |
| 설정 | `.env`, `example.env`, `config.py`, `nuxt.config.ts` 등 설정·환경변수 변경 |
| CI·배포 | `../../../../../.github/workflows`, `Dockerfile`, `docker/`, `.releaserc.json` 등 CI·배포 파일 변경 |
| Git 히스토리 | `git push --force`, `git reset --hard`, push된 커밋의 rebase·amend, 브랜치 삭제 |
| 시스템 | `sudo`, 전역 패키지 설치(`npm -g`, `brew install` 등), 시스템 설정 변경 |
| 요구사항 | 요구사항이 모호하거나 여러 가지로 해석될 수 있는 경우 |
| 지시 | 사람 작업자의 지시에 보안 문제, 컨벤션 위반, 더 나은 방법 등이 보이는 경우 (이유와 대안을 함께 제시) |

#### PR에 기록하고 진행
위에 해당하지 않으며 요구사항에 부합하는 기술적인 판단은 먼저 묻지 않고 진행합니다. 대신 PR 작성시 **결정 사항**에 판단 내용과 이유를 작성합니다.<br />
(예: 구현 방식·알고리즘 선택, 함수·변수 이름, 에러 메시지 문구, 커밋 type 선택)

### 규칙 및 동작
인공지능 작업자가 작업 중 지켜야 하는 규칙과 동작에 대해 설명합니다.
- [판단 범위](#ai-판단범위)를 반드시 지켜야 합니다.
- [Git 규칙](#ai-git)을 반드시 지켜야 합니다.
- PR 작성시 [작성 규칙](#ai-pr-rule)을 준수해야 합니다.
- 작업 종료시 PR 작성 전, [테스트 범위](#ai-test)에 따라 검증해야 합니다.
- `../../../../../api-client/src/gen` 등 자동 생성된 코드는 직접 수정하지 않습니다. 승인받은 API 변경이 있는 경우, 로컬 서버를 켠 상태에서 `yarn sdk-gen`으로 SDK를 다시 생성해 같은 PR에 함께 커밋합니다. ([SDK 생성하기](/api/sdk#sdk-생성하기) 참고)

### Git 규칙 [#ai-git]
인공지능 작업자가 브랜치, 커밋, PR을 다룰 때 지켜야 할 규칙입니다. 기본적으로 [Git 컨벤션](/docs/development/convention#git-컨벤션)을 따릅니다.
- `master`와 `dev`에는 직접 push하지 않습니다. 두 브랜치 모두 push되면 릴리스가 만들어집니다.
- 작업 브랜치는 [브랜치 컨벤션](/docs/development/convention#브랜치)과 같이 `feat/*`, `fix/*`, `docs/*`로 생성합니다.
- 작업이 끝나면 작업 브랜치에서 `dev`로 PR을 작성해 사람 작업자에게 검토를 요청합니다.
- 커밋 메시지는 [커밋 메시지 컨벤션](/docs/development/convention#커밋-메시지)을 따르며, type은 인공지능 작업자가 선택합니다.
- type에 따라 버전이 바뀌므로, 선택한 type과 그 이유를 PR의 **결정 사항**에 작성합니다.
- 커밋에는 `Co-Authored-By` 등 인공지능 작성 표시를 붙이지 않습니다. 인공지능 작업자가 작성한 PR은 [PR 작성 규칙](#ai-pr-rule)의 전용 템플릿으로 구분합니다.

### PR 작성 규칙 [#ai-pr-rule]
인공지능 작업자가 PR을 작성하는 경우 지켜야 할 규칙과 동작에 대해 설명합니다.<br />
PR 본문은 [`../../../../../.github/PULL_REQUEST_TEMPLATE/ai.md`](https://github.com/scfs-miraepass/MIRAE-PASS/blob/master/.github/PULL_REQUEST_TEMPLATE/ai.md) 템플릿 양식에 맞춰 작성합니다.

| 항목 | 내용 | 작은 변경 |
| --- | --- | --- |
| **요구사항** | 사람 작업자가 전달한 요구사항이 무엇인지와 인공지능 작업자의 해석 | 필수 |
| **영향 범위** | `server`, `client`, `admin`, `sdk`, `docs` 중 바뀐 영역 | 필수 |
| **결정 사항** | 인공지능 작업자가 자체적으로 판단한 내용과 그 이유 (커밋 type 포함) | 필수 |
| **검증** | [테스트 범위](#ai-test)에 따라 무엇을 실행해 어떻게 확인했는지와 그 결과 | 필수 |
| **전체 로직 흐름** | 데이터가 어디서 들어와 어떤 순서로 처리되는지 | 생략 가능 |
| **라이프사이클** | [영역별 라이프사이클](#ai-pr-lifecycle) 참고 | 생략 가능 |
| **작성 이유** | 다른 방법 대신 이 방식을 고른 근거 | 생략 가능 |
| **불확실한 점·하지 않은 것** | 확신이 없거나 확인하지 못한 부분, 요청 범위에서 일부러 제외한 것 | 생략 가능 |

**작은 변경**은 로직의 동작이 바뀌지 않는 변경입니다. (예: 오타·문구 수정, 문서, 주석, 코드 포맷)<br />
작은 변경이 아닌 경우 모든 항목을 작성하며, 해당 사항이 없는 항목은 '없음'으로 작성합니다.

#### 영역별 라이프사이클 [#ai-pr-lifecycle]

| 영역 | 작성 내용 |
| --- | --- |
| `client`, `admin` | 컴포넌트가 마운트·업데이트·언마운트될 때 등록되고 정리되는 것 <br />(이벤트 리스너, 타이머, 구독, WebSocket 등) |
| `server` | 요청 처리 중 생성되고 정리되는 자원 (DB 세션·트랜잭션 범위, 캐시 저장·무효화, 스케줄러 작업 등) |

### 테스트 범위 [#ai-test]
인공지능 작업자가 PR 작성 전 진행해야 하는 테스트의 대상과 도구를 설명합니다.

| 대상 | 테스트 |
| --- | --- |
| 순수 로직 | 필수 |
| UI 컴포넌트 | 선택 |

**순수 로직**은 DB, Redis, HTTP, 파일 등 외부 I/O에 접근하지 않고, 입력만으로 결과가 정해지는 함수입니다. (예: 포인트 계산, 값 검증, 데이터 변환, 포맷 유틸)<br />
외부 I/O에 접근하는 코드는 필수 테스트 대상이 아닙니다.

#### 테스트 도구

| 영역 | 도구 |
| --- | --- |
| `server` | pytest |
| `client`, `admin` | vitest |

<Callout type="warning">
    현재 프로젝트에는 테스트 도구가 설치되어 있지 않습니다. 도구가 설치되기 전까지는 테스트 코드 작성 대신 아래 사항을 지킵니다.

    - `yarn typecheck` 및 `ruff check`, `ruff format`을 통과해야 합니다.
    - 어떤 방법으로 검증했는지와 그 결과를 PR에 작성합니다.
    - 인공지능 작업자가 직접 테스트 도구를 설치하지 않습니다. ([판단 범위](#ai-판단범위)의 라이브러리 추가에 해당)
</Callout>

## 사람 작업자

### 규칙 및 동작
사람 작업자로서 무엇을 해야 하며, 지켜야 할 규칙에 대해 설명합니다.
- 인공지능 작업자가 작업 후 PR로 올리고, 사람 작업자가 검토·수정 후 직접 머지합니다. 인공지능 작업자에게 작업을 요청한 사람 작업자가 직접 검토하고 머지할 수 있습니다.
- 인공지능이 생성한 코드를 모두 검토 및 코드 리뷰를 진행해야 합니다.
- 인공지능이 생성한 코드가 어떤 구조로 되어 있는지, 어떻게 동작하는지 모두 이해해야 합니다. 이해하는 과정 중에는 인공지능을 이용할 수 있습니다.
- 인공지능에게 코드 리뷰를 시킬 수 있지만 참고용으로만 사용하며, 사람 작업자의 검토를 대신할 수 없습니다.
- 머지 전 [머지 전 확인](#human-merge-check) 항목을 모두 확인해야 합니다.

### 머지 전 확인 [#human-merge-check]
인공지능 작업자의 PR 템플릿 맨 아래에 있는 **사람 작업자 확인** 체크리스트를 머지하는 사람 작업자가 직접 체크합니다. 인공지능 작업자는 이 체크리스트를 체크하지 않습니다.
- 변경된 코드가 어떤 구조이고 어떻게 동작하는지 인공지능 없이 설명할 수 있다.
- 커밋 type이 변경 내용과 맞아 버전이 의도대로 바뀐다.
- PR에 적힌 검증을 직접 다시 실행하거나 동작을 확인했다.

백엔드(`server`)의 경우 추가적인 [확인 사항](/docs/development/server#머지-전-체크리스트)이 있습니다.
