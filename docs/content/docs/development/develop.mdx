# 개발 환경

소스 코드를 받아 내 컴퓨터에서 미래패스를 실행하는 방법입니다.

## 요구 사항

- [Node.js](https://nodejs.org) 24 이상 (저장소의 `.nvmrc` 참고)
- [uv](https://docs.astral.sh/uv/) (Python 3.14는 uv가 알아서 설치합니다)
- Docker (MySQL·Redis를 띄우거나 전체를 컨테이너로 실행할 때)

## 저장소 준비하기

```bash
git clone https://github.com/scfs-miraepass/MIRAE-PASS.git
cd MIRAE-PASS

corepack enable
yarn install
```

`yarn install`은 `client`, `admin`, `docs`, `api-client` 워크스페이스를 한 번에 설치하고, 커밋 검사용 pre-commit 훅도 설치합니다.

## 실행하기

<Tabs items={['전체를 Docker로', '직접 실행']}>
<Tabs.Tab>

소스 코드로 이미지를 빌드해 운영과 같은 구성으로 실행합니다.

```bash
cp docker/example.env docker/.env   # DB_ROOT_PASSWORD, DB_PASSWORD 채우기
yarn run:docker
```

`http://localhost:3000`으로 접속합니다. 코드를 고친 뒤에는 이미지를 다시 빌드해야 하므로, 화면을 자주 고치는 작업에는 **직접 실행**이 편합니다.

</Tabs.Tab>

### MySQL과 Redis 실행하기

이미 설치된 MySQL·Redis가 있다면 그것을 써도 됩니다. 없다면 Docker로 띄웁니다.

```bash
docker run -d --name miraepass-mysql -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=miraepass \
  -e MYSQL_USER=miraepass -e MYSQL_PASSWORD=miraepass mysql
docker run -d --name miraepass-redis -p 6379:6379 valkey/valkey
```

### 백엔드 실행하기

```bash
cd server
uv sync
cp example.env .env
```

`.env`를 채웁니다. 로컬에서는 HTTP로 접속하므로 `DEBUG=true`로 두어야 로그인 쿠키가 유지됩니다.

```dotenv filename="server/.env"
DATABASE_URL=mysql+aiomysql://miraepass:miraepass@localhost:3306/miraepass
REDIS_URL=redis://localhost:6379
DEBUG=true
ALLOWED_ORIGINS=*
```

```bash
uv run alembic upgrade head
uv run fastapi dev            # http://localhost:8000, API 문서는 /docs
```

### 테스트 사용자 만들기

```bash
uv run python tools/create_test_users.py
```

학생 `1101`~`1105`, 교사, 서비스 계정이 하나씩 만들어집니다. 처음 로그인할 때 비밀번호를 정합니다.

### 프론트엔드 실행하기

저장소 루트에서 실행합니다.

```bash
yarn dev:client                                              # http://localhost:3000
yarn workspace scfs-miraepass-dashboard dev --port 5234      # 관리자
```

`client`는 `/api`를 `localhost:8000`으로, `/admin`을 `localhost:5234`로 넘겨주므로 `http://localhost:3000/admin/`에서 관리자 페이지도 볼 수 있습니다.

</Steps>

## 자주 쓰는 명령어

| 명령 | 설명 |
| --- | --- |
| `yarn dev:client` / `yarn dev:admin` / `yarn dev:docs` | 개발 서버 실행 |
| `yarn build:client` / `yarn build:admin` / `yarn build:docs` | 빌드 |
| `yarn typecheck:client` / `yarn typecheck:admin` | 타입 검사 |
| `yarn typecheck` | pre-commit 검사를 전체 파일에 실행 |
| `yarn sdk-gen` | 백엔드 OpenAPI로 `@miraepass/api-client` 다시 생성 |
| `uv run alembic revision --autogenerate -m "메시지"` | 마이그레이션 생성 (`server`에서) |

## SDK 다시 만들기

API를 바꿨다면 백엔드(`http://localhost:8000`)를 켠 상태에서 SDK를 다시 생성합니다.

```bash
yarn sdk-gen
```

`../../../../api-client/src/gen`은 자동 생성 폴더이니 직접 고치지 마세요.

## 커밋 규칙

[Conventional Commits](https://www.conventionalcommits.org/ko/v1.0.0/)를 따릅니다. 커밋 타입이 곧 다음 버전을 정하므로([배포](/docs/development/deploy#릴리스-흐름) 참고) 정확히 적어 주세요.

```
<type>(<scope>): <description>
```

- `type`: `feat`, `fix`, `perf`, `docs`, `style`, `refactor`, `test`, `build`, `ci`, `chore`, `revert`
- `scope`: `client`, `server`, `admin`, `sdk`, `docs`

<Callout type="info">
커밋할 때 pre-commit이 `server`는 ruff로, `client`·`admin`은 타입 검사로 확인합니다. ruff가 파일을 고쳐 커밋이 멈추면 고쳐진 파일을 다시 `git add`하고 커밋하세요.
</Callout>
