# 프론트엔드 개발 가이드

`client`(학생 · 교사 · 서비스 계정용 앱)와 `admin`(관리자 대시보드)을 개발할 때 따라야 할 구조, 코드 스타일, 규칙을 설명합니다.<br />
개발 환경 구성은 [개발 환경 구성](/docs/development/develop)을, 저장소 공통 규칙은 [프로젝트 구조와 컨벤션](/docs/development/convention)을 참고하세요.

## 기술 스택

두 앱은 같은 기반 위에 만들어져 있습니다.

| 구분 | 사용 기술 |
| --- | --- |
| 프레임워크 | Nuxt 4 (`app/` 디렉토리 구조), Vue 3 |
| 언어 | TypeScript (`strict`) |
| UI | Nuxt UI, Tailwind CSS 4 |
| API 호출 | `@miraepass/api-client` (백엔드 OpenAPI로 생성한 SDK) |
| 유틸 | VueUse |
| 폰트 | Pretendard (`@nuxt/fonts`) |

앱마다 다른 점은 아래와 같습니다.

| | `client` | `admin` |
| --- | --- | --- |
| 사용자 | 학생, 교사, 서비스 계정 | 관리 권한이 있는 사용자 |
| 화면 | 모바일 우선, PWA로 설치해 사용 | 데스크톱 대시보드 |
| 주소 | `/` | `/admin/` (`app.baseURL`) |
| 아이콘 | Phosphor (`i-ph-*`) | Lucide (`i-lucide-*`) |
| 추가 모듈 | `@vite-pwa/nuxt`, `motion-v`, `@nuxtjs/device` | `@vueuse/nuxt`, `@tanstack/table-core`, `@unovis/vue` |

## 코드 스타일

### 기본 규칙

- 모든 컴포넌트와 페이지는 `<script setup lang="ts">`로 작성합니다. Options API는 쓰지 않습니다.
- 파일 순서는 `<script setup>` → `<template>` → `<style>`(필요한 경우만)입니다.
- 들여쓰기는 **4칸**입니다.
- 별도의 포매터(Prettier, ESLint)는 없습니다. 고치는 파일의 기존 스타일(따옴표, 세미콜론)을 따르고, 새 파일은 큰따옴표와 세미콜론을 사용합니다.
- TypeScript `strict` 모드입니다. `any`는 가능하면 피하고, 꼭 필요하면 이유를 주석으로 남깁니다.
- 주석은 한국어로 씁니다.

### 이름 짓기

| 대상 | 규칙 | 예시 |
| --- | --- | --- |
| 컴포넌트 파일 | 화면(도메인)별 폴더 + `camelCase` | `components/karaoke/detail/bidForm.vue` |
| 페이지 파일 | `camelCase`, 폴더 구조가 곧 URL | `pages/system/userSelect.vue` → `/system/userSelect` |
| 동적 경로 | `[파라미터]` | `pages/karaoke/[id]/party.vue` |
| 상태 composable | `use` + `PascalCase` | `useSession`, `useKaraokeSocket` |
| 동작 composable | 동사로 시작 | `fetchSession` |
| 유틸 함수 | `camelCase` | `karaokeTimeLabel`, `hasPermission` |
| 상수 | `UPPER_SNAKE_CASE` | `KARAOKE_BID_UNIT` |
| `useState` · `useAsyncData` 키 | `{도메인}.{이름}` | `"session.user"`, `"grant_point.point_limit"` |

컴포넌트는 Nuxt 자동 import 규칙에 따라 폴더 경로가 이름이 됩니다. `components/karaoke/list/card.vue`는 `<KaraokeListCard />`로 사용합니다.

<Callout type="info">
    `useState`와 `useAsyncData`의 키는 앱 전체에서 공유됩니다. 다른 화면과 겹치지 않도록 반드시 도메인을 앞에 붙여 주세요.
</Callout>

### Props와 Emits

타입 기반 선언을 사용합니다.

```vue filename="components/karaoke/list/card.vue"
<script setup lang="ts">
import type { KaraokeResponse } from "@miraepass/api-client";

defineProps<{
    item: KaraokeResponse;
}>();
defineEmits<{ click: [] }>();
</script>
```

### 타입

- API와 관련된 타입(`User`, `KaraokeResponse`, `UserPermission`, Enum 등)은 직접 만들지 않고 `@miraepass/api-client`에서 가져옵니다.
- 타입만 가져올 때는 `import type`을 사용합니다.
- SDK에 없는 타입(WebSocket 메시지 등)만 직접 정의하고, 어떤 백엔드 모델과 대응하는지 주석으로 남깁니다.

## API 호출하기

### SDK 사용

API는 URL을 직접 적지 않고 전역 `$API`(SDK 인스턴스)로 호출합니다. SDK의 자세한 사용법은 [SDK 사용하기](/api/sdk)를 참고하세요.

```ts
const req = await $API.getQuestQuestQuestIdGet({ path: { quest_id: 1 } });

if (req.error) {
    // 실패: req.error.message 에 서버의 에러 메시지
    return;
}
const quest = req.data.data; // 성공: ResponseModel의 data
```

- 결과는 `{ data, error, response }` 형태입니다. **항상 `req.error`를 먼저 확인**합니다.
- 응답 헤더(`X-MAX-PAGE` 등)는 `req.response.headers.get("X-MAX-PAGE")`로 읽습니다.
- 개발 환경에서는 `/api/**` 요청이 `http://localhost:8000`으로 프록시됩니다.

<Callout type="warning">
    `_fetch`, `useAPI`는 SDK 도입 전에 쓰던 코드입니다. 새 코드에서는 `$API`를 사용하세요.
</Callout>

### 페이지에서 데이터 불러오기

화면에 필요한 데이터는 `useAsyncData`로 불러옵니다. 키를 지정하고, 페이지를 떠날 때 요청이 취소되도록 `signal`을 넘깁니다.

```ts
const queryParams = computed(() => ({ limit: 20, page: page.value }));

const { data, pending, refresh } = await useAsyncData(
    "users.list",
    async (_nuxtApp, { signal }) => {
        const req = await $API.getUsersAdminUsersGet({ query: queryParams.value, signal });
        if (req.error) return;
        maxPage.value = Number(req.response.headers.get("X-MAX-PAGE"));
        return req.data;
    },
    { watch: [queryParams] }, // 조건이 바뀌면 다시 불러오기
);
```

짧은 시간 동안 같은 데이터를 다시 요청하지 않으려면 `getCachedData`로 만료 시간을 둡니다. (`components/home/section/grantPoint.vue` 참고)

### 에러 보여주기

요청이 실패하면 `useToast()`로 알려줍니다. 서버가 보낸 `message`를 그대로 보여줄 수 있습니다.

```ts
const toast = useToast();

if (req.error) {
    toast.add({ title: "처리하지 못했어요.", description: karaokeErrorMessage(req.error), color: "error" });
    return;
}
toast.add({ title: "초대를 수락했어요.", color: "success" });
```

### WebSocket

노래방 실시간 경매(`/karaoke/{id}/ws`)는 SDK에 포함되지 않습니다. `client`의 `useKaraokeSocket`을 사용하세요.<br />
Nitro의 `routeRules` 프록시는 WebSocket을 중계하지 못하므로, `client/server/api/karaoke/[id]/ws.ts`가 백엔드로 직접 연결을 넘겨줍니다.

## 로그인과 세션

| 이름 | 위치 | 역할 |
| --- | --- | --- |
| `useSession()` | `composables/useSession.ts` | 로그인한 사용자 정보 (`localStorage`의 `session.user`) |
| `useAuth()` | `composables/useAuth.ts` | 세션을 마지막으로 확인한 시각 |
| `fetchSession()` | `composables/fetchSession.ts` | 서버에서 세션을 다시 받아 갱신 (중복 요청 방지) |
| `auth.global.ts` | `middleware/` | 페이지 이동마다 로그인 여부 확인, 미로그인 시 `/login`으로 이동 |

- 로그인 상태에서는 세션 정보를 **5분** 동안 캐시하고, 지나면 페이지 이동 시 다시 확인합니다.
- `useSession()`의 값은 최대 5분 전 값일 수 있습니다. 포인트처럼 정확해야 하는 값은 API로 직접 받아 오세요.
- 세션 정보를 바로 갱신해야 하면 `fetchSession()`을 호출합니다.

## 권한 처리

### 페이지 권한

페이지에 필요한 권한은 `definePageMeta`에 적습니다. 권한이 없으면 `permissions.global.ts` 미들웨어가 403 에러 페이지를 띄웁니다.

```vue filename="pages/karaoke/index.vue"
<script setup lang="ts">
definePageMeta({
    permissions: [UserPermission.VIEW_KARAOKE] as PermissionCondition,
});
</script>
```

### 화면 안에서 권한 확인

버튼이나 섹션을 권한에 따라 보여줄 때는 `utils/permission.ts`의 `hasPermission`을 사용합니다. 비트 연산을 직접 쓰지 않습니다.

```ts
// 하나의 권한
hasPermission(session.value?.permissions, UserPermission.NO_LIMIT_POINT);

// 모두 필요 (AND)
hasPermission(session.value?.permissions, [UserPermission._GRANT_POINT, UserPermission.SEARCH_USER]);

// 하나라도 있으면 (OR)
hasPermission(session.value?.permissions, { or: [UserPermission._GRANT_POINT, UserPermission._DEDUCT_POINT] });
```

<Callout type="warning">
    프론트엔드의 권한 확인은 **화면을 위한 것**입니다. 실제 권한 검사는 반드시 서버에서도 해야 합니다.
</Callout>

권한 목록과 의미는 [권한](/api/permissions) 문서를 참고하세요.

## UI 작성하기

### Nuxt UI와 Tailwind

- 버튼, 입력, 모달, 토스트 등은 Nuxt UI 컴포넌트(`UButton`, `UInput`, `UModal`, `useToast` …)를 먼저 사용합니다.
- 스타일은 Tailwind 클래스로 작성합니다. 색은 Nuxt UI의 의미 색(`primary`, `neutral`, `success`, `warning`, `error`)과 `bg-default`, `bg-muted`, `bg-elevated` 같은 토큰을 사용합니다.
- 라이트 · 다크 모드는 `light:` · `dark:` 변형으로 함께 처리합니다.
- 기본 색(`primary`)은 `app.config.ts`에서 `blue`로 설정되어 있습니다.

### 글자 크기 (`client`)

`client`는 `assets/styles/main.css`에 글자 크기 토큰을 정의해 두었습니다. 임의의 크기(`text-[15px]`) 대신 아래 토큰을 사용합니다.

| 토큰 | 크기 | 용도 |
| --- | --- | --- |
| `text-h1` ~ `text-h6` | 52px ~ 32px | 큰 숫자, 제목 |
| `text-p0` | 20px | 강조 본문 |
| `text-p1` | 18px | 본문 |
| `text-p2` | 14px | 보조 본문 |
| `text-p3` | 10px | 작은 라벨 |
| `text-ui-p1`, `text-ui-p2` | 18px, 14px | 버튼 · 설명 등 UI 텍스트 (얇은 굵기) |

### 모달 (`admin`)

`admin`의 모달은 아래 형태로 만듭니다.

- 부모는 `v-if`로 모달을 띄우고, `@close` · `@success` 이벤트를 받습니다.
- 모달은 안쪽에 `open` 상태를 두고, 닫힐 때 애니메이션이 끝난 뒤(`200ms`) `close`를 보냅니다.

```vue
<!-- 부모 -->
<PointManageModal
    v-if="isPointManageModalOpen"
    :users="selectedUsers"
    @close="isPointManageModalOpen = false"
    @success="() => { isPointManageModalOpen = false; refresh(); }"
/>
```

```ts
// 모달 (components/users/userPointManageModal.vue)
const emit = defineEmits(["close", "success"]);
const open = ref<boolean>(true);

watch(open, (value) => {
    if (!value) setTimeout(() => emit("close"), 200);
});
```

### 모바일 · PWA (`client`)

- `client`는 휴대폰 세로 화면을 기준으로 만듭니다. 화면을 만들면 브라우저 개발자 도구의 모바일 화면으로 꼭 확인하세요.
- iOS에서는 개발 서버로 PWA가 제대로 동작하지 않습니다. PWA를 확인하려면 빌드해서 실행합니다.

```bash
yarn workspace scfs-miraepass-front dev:build
```

## 새 페이지 추가하기

<Steps>

    ### 페이지 파일 만들기

    `app/pages/` 아래에 원하는 URL 구조대로 파일을 만듭니다.

    ### 권한 설정

    로그인한 사용자 중 일부만 들어올 수 있다면 `definePageMeta({ permissions: [...] })`를 적습니다.

    ### 컴포넌트 나누기

    화면이 길어지면 `app/components/{도메인}/` 아래로 컴포넌트를 나눕니다.

    ### 데이터 연결

    `useAsyncData` + `$API`로 데이터를 불러오고, 실패하면 토스트로 알려줍니다. 필요한 API가 없거나 응답이 부족하면 백엔드를 먼저 수정하고 SDK를 다시 만듭니다. ([SDK 생성하기](/api/sdk#sdk-생성하기))

    ### 진입점 연결

    홈 화면(`pages/index.vue`)이나 메뉴에서 새 페이지로 이동할 수 있게 연결합니다. 진입 버튼도 같은 권한으로 숨겨야 합니다.

</Steps>

## 커밋 전 체크리스트

- [ ] `yarn typecheck:client` / `yarn typecheck:admin`이 통과한다. (pre-commit 훅이 자동 실행)
- [ ] API를 SDK(`$API`)로 호출하고, `req.error`를 처리했다.
- [ ] 권한이 필요한 페이지에 `definePageMeta({ permissions })`를 적었다.
- [ ] `useState` · `useAsyncData` 키에 도메인을 붙였다.
- [ ] 라이트 · 다크 모드에서 모두 확인했다. (`client`는 모바일 화면도 확인)
- [ ] 커밋 메시지는 `feat(client): ...`, `fix(admin): ...` 형식이다. ([커밋 메시지](/docs/development/convention#커밋-메시지))
