# AI 이용 가이드
이 문서에서는 생성형 인공지능을 미래패스 개발에 사용하는 경우, 생성형 인공지능의 사용 가이드라인을 설명합니다.

## 정의
인공지능과 사람 작업자를 철저하게 구분해야 합니다.<br />
본 문서에서는 생성형 인공지능을 '인공지능 작업자' 라고 하며, 그 인공지능을 사용하는 사람을 '사람 작업자' 라고 합니다.

## 공통 규칙 및 동작
인공지능 작업자 및 사람 작업자 모두가 지켜야한 규칙 및 동작에 대해 설명합니다.
- [코드 컨벤션](/docs/development/convention#코드-컨벤션)을 반드시 지켜야 합니다.
- 인공지능 작업자 및 사람 작업자는 수직 관계가 아닌 수평적인 관계이며. 인공지능 작업자 또한 사람 작업자에게 제안, 질문, 지적 등의 행동을 할 수 있습니다.

## 인공지능 작업자

### 판단 범위 [#ai-판단범위]
AI가 판단을 진행 할 경우 아래의 사항을 반드시 지켜야 합니다.
- **라이브러리 추가**와 **구상서의 구조·컨벤션 변경**은 반드시 사람 작업자에게 먼저 묻습니다.
- 요구사항의 부합하지만, 기술과 관련된 것을 판단해야 하는 경우 PR 작성시 결정 사항에 작성 후 진행합니다.

### 규칙 및 동작
인공지능 작업자가 작업 중 지켜야하는 규칙과 동작에 대해 설명합니다.
- [판단 범위](#ai-판단범위)를 반드시 지켜야 합니다.
- 작업 종료시 인공지능 작업자는 master에 직접 push하지 않으며, 브랜치를 생성 후 PR를 작성해 사람 작업자에게 검토를 요청해야 합니다.
- PR 작성시 [작성 규칙](#ai-pr-rule)를 준수해야 합니다.
- 작업 종료시 PR 작성 전, 순수 로직은 필수로 테스트를 해야하며, UI 컴포넌트 테스트는 선택적으로 진행할 수 있습니다.

### PR 작성 규칙 [#ai-pr-rule]
인공지능 작업자가 PR를 작성하는 경우 지켜야할 규칙과 동작에 대해 설명합니다.
- **전체 로직 흐름**: 데이터가 어디서 들어와 어떤 순서로 처리되는지
- **라이프사이클**: 컴포넌트가 마운트·업데이트·언마운트될 때 실행되고 정리되는 것 (이벤트 리스너, 타이머, 구독 등)
- **작성 이유**: 다른 방법 대신 이 방식을 고른 근거
- **결정 사항**: 인공지능이 여러 이유로 자체적인 판단시, 해당 판단을 왜 했으며 결정하게된 이유와 방법 등을 작성합니다.
- **요구사항**: 사람 작업자가 전다라한 요구사항이 무엇인지와 인공지능 작업자의 해석

### 테스트 범위

- 필수: 순수 로직
- 선택: UI 컴포넌트 테스트

## 사람 작업자

### 규칙 및 동작
사람 작업자로써 무엇을 해야하며, 지켜야할 규칙에 대해 설명합니다.
- 인공지능 작업자가 작업 후 PR로 올리고, 사람 작업자가 검토·수정 후 직접 머지합니다.
- 인공지능이 생성한 코드를 모두 검토 및 코드 리뷰를 진행해야 합니다.
- 인공지능이 생성한 코드가 어떤 구조로 되어있는지, 어떻게 동작하는지 모두 이해 해야합니다. 이해하는 과정 중에는 인공지능을 이용할 수 있습니다.
