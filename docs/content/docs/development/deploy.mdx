# 배포

미래패스는 GitHub Actions가 버전을 정하고 Docker 이미지를 빌드해 올립니다. 운영 서버는 새 이미지를 받아 다시 시작하기만 하면 됩니다.

## 릴리스 흐름

`master` 또는 `dev` 브랜치에 push하면 [`../../../../.github/workflows/release.yml`](https://github.com/scfs-miraepass/MIRAE-PASS/blob/master/.github/workflows/release.yml)이 실행됩니다.

1. **버전 결정**: [semantic-release](https://semantic-release.gitbook.io)가 커밋 메시지([Conventional Commits](https://www.conventionalcommits.org/ko/v1.0.0/))를 읽고 다음 버전을 정합니다.
   - `feat` → Minor, `fix`·`perf` → Patch, `BREAKING CHANGE` → Major
   - 릴리스할 커밋이 없으면 여기서 끝나고 이미지도 빌드하지 않습니다.
2. **버전 반영**: `client`, `admin`, `server`의 버전을 한 번에 올리고 `../../../../CHANGELOG.md`와 함께 `chore(release): x.y.z [skip ci]` 커밋과 `vx.y.z` 태그를 만듭니다.
3. **이미지 빌드**: 새 태그를 기준으로 세 이미지를 빌드해 GitHub Container Registry에 올립니다.

## 이미지와 태그

| 이미지 |
| --- |
| `ghcr.io/scfs-miraepass/mirae-pass/client` |
| `ghcr.io/scfs-miraepass/mirae-pass/admin` |
| `ghcr.io/scfs-miraepass/mirae-pass/server` |

| 태그 | 붙는 경우 |
| --- | --- |
| `x.y.z` | 모든 릴리스 (예: `1.14.1`, `1.15.0-dev.1`) |
| `latest` | `master` 브랜치 릴리스 |
| `dev` | `dev` 브랜치 릴리스 (프리릴리스 `x.y.z-dev.n`) |

운영용 `docker-compose.yml`은 `latest` 태그를 사용합니다.

## 서버 업데이트하기

<Steps>

### 새 이미지 받기

```bash
cd miraepass
docker compose pull
```

### 다시 시작하기

```bash
docker compose up -d
```

이미지가 바뀐 컨테이너만 다시 만들어집니다. `server`는 시작할 때 데이터베이스 마이그레이션(`alembic upgrade head`)을 자동으로 적용합니다.

### 확인하기

```bash
docker compose ps
docker compose logs -f server
```

모든 API 응답에는 `X-Server-Version` 헤더로 서버 버전이 붙습니다.

</Steps>

<Callout type="warning">
마이그레이션이 포함된 업데이트는 되돌리기 어렵습니다. 업데이트 전에 [백업](#백업)을 먼저 해 두세요.
</Callout>

## 특정 버전으로 고정하기

`latest` 대신 버전을 적으면 그 버전으로 고정됩니다. 문제가 생긴 업데이트를 되돌릴 때도 같은 방법을 씁니다.

```yaml filename="docker-compose.yml" {3}
services:
  client:
    image: ghcr.io/scfs-miraepass/mirae-pass/client:1.14.1
```

`client`, `admin`, `server`는 같은 버전을 함께 쓰도록 만들어졌으므로 세 이미지의 버전을 맞춰 주세요.

<Callout type="error">
이전 버전으로 되돌려도 데이터베이스 스키마는 자동으로 되돌아가지 않습니다. 새 버전에서 마이그레이션이 적용됐다면 백업을 복원하거나 컨테이너 안에서 `uv run alembic downgrade`를 직접 실행해야 합니다.
</Callout>

## 수동 릴리스

semantic-release를 거치지 않고 원하는 버전으로 릴리스하려면 GitHub의 **Actions → Docker Image Release → Run workflow**에서 `manual_version`에 버전(예: `1.15.0`)을 입력합니다.
버전에 `-`가 들어가면(예: `1.15.0-rc.1`) 프리릴리스로 표시됩니다.

## 릴리스에 필요한 저장소 설정

릴리스 커밋을 보호된 브랜치에 push하기 위해 GitHub App 토큰을 사용합니다. 저장소 **Settings → Secrets and variables → Actions**에 아래 값이 있어야 합니다.

| Secret | 내용 |
| --- | --- |
| `RELEASE_APP_ID` | 릴리스용 GitHub App의 App ID |
| `RELEASE_APP_PRIVATE_KEY` | 그 App의 Private key |

App은 저장소에 설치되어 있어야 하고, 브랜치 보호 규칙을 우회할 수 있어야 합니다.

## 백업

데이터는 MySQL에 있습니다. `mysqldump`로 백업합니다.

```bash
docker compose exec database sh -c 'mysqldump -u root -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"' > backup-$(date +%F).sql
```

복원은 아래처럼 합니다.

```bash
docker compose exec -T database sh -c 'mysql -u root -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"' < backup-2026-11-04.sql
```

Redis에는 로그인 세션과 캐시만 있으므로 백업하지 않아도 됩니다. Redis가 초기화되면 모든 사용자가 다시 로그인해야 합니다.
