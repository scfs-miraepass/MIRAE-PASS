## 왜 Docker가 필요할까?

친구에게 내가 만든 게임을 보내줬는데 이런 말을 들은 적 있나요?

> "내 컴퓨터에서는 안 열리는데?"

프로그램은 혼자서 돌아가지 않습니다. 운영체제의 종류와 버전, 미리 깔려 있어야 하는 다른 프로그램(라이브러리), 설정 파일 등이 맞아야 실행됩니다.
내 컴퓨터에는 이런 것들이 우연히 다 갖춰져 있었지만, 친구 컴퓨터에는 없었던 것이죠.

미래패스도 마찬가지입니다. 제대로 돌아가려면 이런 것들이 필요합니다.

- 웹 화면을 위한 **Node.js 24**
- 서버 프로그램을 위한 **Python 3.14**와 수십 개의 라이브러리
- 데이터를 저장할 **MySQL**
- 로그인 정보를 잠깐 보관할 **Redis**

이걸 학교 서버에 하나하나 설치하고 버전을 맞추는 건 번거롭고 실수하기 쉽습니다. 몇 년 뒤 다른 선생님이나 후배가 서버를 옮기려 할 때는 더 어렵습니다.

**Docker는 프로그램과 그 프로그램에 필요한 모든 것을 한 상자에 담아서, 어느 컴퓨터에서든 똑같이 실행되게 해 주는 도구입니다.**

## 컨테이너 = 화물 컨테이너

Docker라는 이름과 로고(고래 위에 쌓인 상자)는 바다를 오가는 **화물 컨테이너**에서 왔습니다.

화물 컨테이너가 생기기 전에는 배에 짐을 실을 때마다 상자, 자루, 통을 하나하나 다르게 옮겨야 했습니다.
그런데 크기가 정해진 철제 컨테이너가 생기자, 안에 무엇이 들었든 **똑같은 크레인으로 들어서 똑같은 배와 트럭에 실을 수 있게** 되었습니다.

Docker의 **컨테이너**도 같은 생각입니다.

| 화물 컨테이너 | Docker 컨테이너 |
| --- | --- |
| 안에 옷이 들었든 전자제품이 들었든 겉모양은 같다 | 안에 Python 프로그램이 들었든 MySQL이 들었든 다루는 방법은 같다 |
| 어느 배, 어느 항구에서든 실을 수 있다 | Docker만 설치되어 있으면 어느 컴퓨터에서든 실행된다 |
| 컨테이너끼리 내용물이 섞이지 않는다 | 컨테이너끼리 서로의 파일이나 설정을 건드리지 않는다 |

## 핵심 용어 세 가지

Docker를 쓰다 보면 이미지, 컨테이너, 레지스트리라는 말이 계속 나옵니다. **요리**에 비유하면 쉽습니다.

### 이미지 (Image) — 밀키트 [#image]

**이미지**는 프로그램을 실행하는 데 필요한 모든 것을 담아 둔 **꾸러미**입니다.
재료와 조리법이 다 들어 있는 **밀키트**를 떠올리면 됩니다.

- 이미지 자체는 실행되지 않습니다. 냉장고에 있는 밀키트처럼 그냥 보관되어 있을 뿐입니다.
- 한 번 만들어진 이미지는 바뀌지 않습니다. 같은 밀키트로 요리하면 언제나 같은 맛이 나죠.

미래패스에는 `client`, `admin`, `server` 세 개의 이미지가 있습니다.

### 컨테이너 (Container) — 밀키트로 만든 요리 [#container]

**컨테이너**는 이미지를 실제로 **실행한 것**입니다. 밀키트를 뜯어서 요리한 결과물이죠.

- 밀키트 하나로 요리를 여러 번 할 수 있듯이, 이미지 하나로 컨테이너를 여러 개 만들 수 있습니다.
- 컨테이너를 지워도 이미지는 남아 있어서, 언제든 다시 새 컨테이너를 만들 수 있습니다.

<Callout type="info">
**프로그램과 실행 중인 프로그램**의 관계와 비슷합니다. 컴퓨터에 설치된 카카오톡 파일이 이미지라면, 실행해서 화면에 떠 있는 카카오톡 창이 컨테이너입니다.
</Callout>

### 레지스트리 (Registry) — 밀키트 판매점 [#registry]

**레지스트리**는 이미지를 올려 두고 내려받는 **저장소**입니다. 밀키트를 파는 온라인 쇼핑몰이라고 생각하면 됩니다.

- 가장 유명한 곳은 [Docker Hub](https://hub.docker.com)입니다. MySQL, Redis 같은 유명한 프로그램의 이미지가 다 여기 있습니다.
- 미래패스의 이미지는 GitHub가 운영하는 레지스트리인 `ghcr.io`에 올라가 있습니다.

```
레지스트리 (ghcr.io)  ──내려받기(pull)──▶  이미지  ──실행(run)──▶  컨테이너
   밀키트 판매점                          밀키트                   완성된 요리
```

## 이미지는 어떻게 만들까? — Dockerfile

밀키트를 만들려면 **레시피**가 필요합니다. Docker에서는 이 레시피를 **Dockerfile**이라는 파일에 적습니다.

미래패스 서버의 Dockerfile을 쉽게 풀어 보면 이렇습니다.

```dockerfile filename="server/Dockerfile"
FROM python:3.14-slim          # 1. Python 3.14가 설치된 기본 상자에서 시작한다
WORKDIR /app                   # 2. 상자 안에 /app 이라는 작업 폴더를 만든다
COPY . .                       # 3. 서버 소스 코드를 상자 안에 복사한다
RUN uv sync --locked           # 4. 필요한 라이브러리를 설치한다
EXPOSE 8000                    # 5. 8000번 문(포트)을 쓸 거라고 알려 둔다
CMD ["uv", "run", "uvicorn", ...]  # 6. 컨테이너가 켜지면 서버 프로그램을 실행한다
```

(실제 파일은 조금 더 깁니다. 위는 흐름만 보여 주기 위해 줄인 것입니다.)

이 레시피대로 이미지를 만드는 것을 **빌드(build)** 라고 합니다. 미래패스는 코드가 바뀔 때마다 GitHub가 자동으로 빌드해서 레지스트리에 올려 줍니다. 그래서 학교 서버에서는 직접 빌드할 필요 없이 **내려받기만** 하면 됩니다.

## 가상 머신과 뭐가 다를까?

"컴퓨터 안에 또 다른 컴퓨터를 만드는 것"이라고 하면 **가상 머신**(VirtualBox, VMware 등)을 떠올릴 수도 있습니다. 비슷해 보이지만 차이가 있습니다.

| | 가상 머신 | Docker 컨테이너 |
| --- | --- | --- |
| 비유 | 아파트 안에 **집을 통째로 한 채 더** 짓기 | 한 집 안에 **칸막이로 방을 나누기** |
| 운영체제 | 컨테이너마다 운영체제 전체를 따로 실행 | 컴퓨터의 운영체제를 함께 사용 |
| 크기 | 수 GB | 수십~수백 MB |
| 켜지는 시간 | 수십 초 ~ 몇 분 | 1~2초 |

컨테이너는 훨씬 가볍기 때문에, 미래패스처럼 프로그램 다섯 개를 한 서버에서 동시에 돌려도 부담이 적습니다.

## 여러 컨테이너를 한 번에 — Docker Compose

미래패스는 컨테이너 **다섯 개**가 함께 일합니다.

| 컨테이너 | 하는 일 | 식당에 비유하면 |
| --- | --- | --- |
| `client` | 학생·교사가 보는 웹 화면 | 손님을 맞는 **홀 직원** |
| `admin` | 관리자 화면 | 사장님 **사무실** |
| `server` | 포인트 지급, 로그인 같은 실제 처리 | 요리하는 **주방** |
| `database` (MySQL) | 사용자·포인트 기록을 영구 보관 | 재료를 보관하는 **창고** |
| `redis` | 로그인 상태처럼 자주 쓰는 정보를 잠깐 보관 | 바로 꺼내 쓰는 **조리대 위 선반** |

이 다섯 개를 하나씩 따로 켜고, 서로 연결하고, 켜는 순서까지 맞추려면 명령어를 아주 많이 입력해야 합니다.
**Docker Compose**는 이 모든 내용을 `docker-compose.yml`이라는 파일 하나에 적어 두고, **명령어 한 줄로 전부 켜고 끌 수 있게** 해 줍니다.

```yaml filename="docker-compose.yml (일부)"
services:
  client:                                   # 컨테이너 이름
    image: ghcr.io/scfs-miraepass/mirae-pass/client:latest   # 사용할 이미지
    ports:
      - "3000:3000"                         # 바깥과 연결할 문(포트)
  server:
    image: ghcr.io/scfs-miraepass/mirae-pass/server:latest
    depends_on:                             # database와 redis가 먼저 켜져야 한다
      - database
      - redis
```

```bash
docker compose up -d     # 다섯 개 모두 켜기
docker compose down      # 다섯 개 모두 끄기
```

## 알아 두면 좋은 개념

### 포트 (Port) — 건물의 출입문 번호

컴퓨터 한 대에서 여러 프로그램이 동시에 인터넷과 통신하기 때문에, 각 프로그램은 **번호가 붙은 문**을 하나씩 씁니다. 이 번호를 **포트**라고 합니다.

- 웹 화면(`client`)은 3000번 문
- 서버(`server`)는 8000번 문
- MySQL은 3306번 문

`"3000:3000"`은 **"서버 컴퓨터의 3000번 문으로 들어온 손님을 컨테이너의 3000번 문으로 안내해라"** 라는 뜻입니다.
미래패스는 `client`의 3000번 문 **하나만** 바깥에 열어 두고, 나머지 컨테이너는 바깥에서 직접 들어올 수 없게 막아 두었습니다. 그래서 더 안전합니다.

### 네트워크 — 컨테이너끼리의 내선 전화

컨테이너들은 서로 격리되어 있지만, 같은 **네트워크**에 넣어 주면 서로 대화할 수 있습니다.
회사 안 **내선 전화**처럼, 같은 네트워크 안에서는 이름만으로 서로를 부를 수 있습니다.

예를 들어 `server` 컨테이너는 데이터베이스 주소를 `database:3306`이라고만 적어도 MySQL 컨테이너를 찾아갑니다. 미래패스의 컨테이너들은 모두 `miraepass-net`이라는 네트워크에 들어 있습니다.

### 볼륨 (Volume) — 지워지지 않는 사물함

컨테이너는 **언제든 지우고 다시 만들 수 있는 일회용**입니다. 새 버전으로 업데이트할 때도 기존 컨테이너를 지우고 새 이미지로 다시 만듭니다.
그런데 컨테이너 안에 저장된 데이터는 컨테이너를 지우면 **함께 사라집니다.** 학생들의 포인트 기록이 업데이트할 때마다 사라지면 큰일이겠죠?

**볼륨**은 컨테이너 바깥, 즉 서버 컴퓨터에 데이터를 따로 보관하는 **사물함**입니다. 컨테이너가 바뀌어도 사물함의 물건은 그대로 남습니다.

```yaml
database:
  volumes:
    - ./data:/var/lib/mysql   # 서버의 data 폴더 ↔ 컨테이너 안의 MySQL 데이터 폴더
```

<Callout type="warning">
그래서 미래패스 설치 폴더의 `data/` 폴더는 **절대 지우면 안 됩니다.** 이 폴더가 곧 모든 사용자와 포인트 기록입니다.
</Callout>

### 환경 변수 — 상자 밖에서 넣어 주는 설정

같은 이미지라도 학교마다, 서버마다 비밀번호나 주소 같은 설정은 다릅니다. 이런 값을 이미지 안에 적어 두면 바꿀 때마다 이미지를 다시 만들어야 하죠.
**환경 변수**는 컨테이너를 실행할 때 **바깥에서 설정값을 건네주는** 방법입니다. 미래패스는 `.env` 파일에 적어 둔 값을 컨테이너에 전달합니다.

```dotenv filename=".env"
DB_PASSWORD=비밀번호
```

비밀번호가 이미지 안에 들어 있지 않으니, 이미지를 인터넷에 공개해도 안전합니다.

## 자주 쓰는 명령어

미래패스 설치 폴더에서 실행합니다.

| 명령어 | 하는 일 |
| --- | --- |
| `docker compose up -d` | 모든 컨테이너를 백그라운드에서 켜기 |
| `docker compose down` | 모든 컨테이너를 끄고 지우기 (볼륨의 데이터는 남음) |
| `docker compose ps` | 컨테이너들이 잘 켜져 있는지 보기 |
| `docker compose logs -f server` | `server` 컨테이너가 출력하는 기록을 실시간으로 보기 (`Ctrl + C`로 나가기) |
| `docker compose pull` | 레지스트리에서 새 이미지 내려받기 |
| `docker compose restart server` | `server` 컨테이너만 다시 시작하기 |
| `docker compose exec server sh` | `server` 컨테이너 안으로 들어가서 명령어 입력하기 (`exit`로 나오기) |

## 한눈에 정리

<Steps>

### 레시피를 쓴다

개발자가 **Dockerfile**에 프로그램을 어떻게 준비할지 적습니다.

### 밀키트를 만든다

Dockerfile대로 **이미지**를 **빌드**합니다. 미래패스는 GitHub가 자동으로 해 줍니다.

### 판매점에 올린다

이미지를 **레지스트리**(`ghcr.io`)에 올립니다.

### 학교 서버에서 받아서 요리한다

학교 서버에서 이미지를 **내려받아(pull)** **컨테이너**로 **실행(run)** 합니다. **Docker Compose**가 다섯 개의 컨테이너를 한 번에 켜 줍니다.

### 중요한 건 사물함에

데이터는 **볼륨**에 저장되어, 컨테이너를 바꿔도 사라지지 않습니다.

</Steps>
