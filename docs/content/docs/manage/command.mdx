# 자주 사용하는 명령어

미래패스를 운영하면서 자주 쓰는 Docker Compose 명령어를 모았습니다.<br />
모든 명령은 [설치](/docs/getting-started/install)할 때 만든 `miraepass` 폴더(`docker-compose.yml`이 있는 폴더)에서 실행합니다.

```bash
cd miraepass
```

<Callout type="info">
    명령어에 나오는 `client`, `admin`, `server`, `database`, `redis`는 `docker-compose.yml`에 적힌 **서비스 이름**입니다.
    각 서비스가 하는 일은 [아키텍쳐](/docs/architecture)를 참고하세요.
</Callout>

## 명령 요약

| 하려는 일 | 명령 |
| --- | --- |
| 서비스 시작 | `docker compose up -d` |
| 서비스 중지 | `docker compose stop` |
| 서비스 재시작 | `docker compose restart` |
| 상태 확인 | `docker compose ps` |
| 로그 보기 | `docker compose logs -f server` |
| 설정(`.env`) 변경 적용 | `docker compose up -d` |
| 업데이트 | `docker compose pull && docker compose up -d` |
| 사용자·포인트 관리 | `docker compose exec server uv run python tools/cli.py` |

## 서비스 시작과 종료 관련

### 시작하기

```bash
docker compose up -d
```

- 컨테이너가 없으면 새로 만들고, 멈춰 있으면 다시 실행합니다.
- `-d`를 붙이면 터미널을 닫아도 계속 실행됩니다. 빼면 로그가 화면에 출력되고, `Ctrl + C`를 누르면 서비스가 멈춥니다.
- `server`는 `database`와 `redis`가 준비된 뒤에 시작되므로, 접속까지 10~15초 정도 걸릴 수 있습니다.

### 중지하기

```bash
docker compose stop
```

컨테이너를 멈추기만 하고 지우지는 않습니다. 다시 실행할 때는 `docker compose start` 또는 `docker compose up -d`를 사용합니다.

### 재시작하기

```bash
# 전체 재시작
docker compose restart

# 특정 서비스만 재시작
docker compose restart server
```

화면이 멈추거나 서버가 응답하지 않을 때 먼저 시도해 볼 수 있습니다.

<Callout type="warning">
    `restart`는 `.env`나 `docker-compose.yml`의 변경 사항을 **반영하지 않습니다.** 설정을 바꿨다면 [설정 변경 적용하기](#설정-변경-적용하기)를 참고하세요.
</Callout>

### 컨테이너 삭제하기

```bash
docker compose down
```

컨테이너와 네트워크를 지웁니다. `data/`(데이터베이스)와 `logs/` 폴더는 지워지지 않으므로, `docker compose up -d`로 다시 실행하면 데이터가 그대로 남아 있습니다.

<Callout type="warning">
    `down`은 `redis` 컨테이너도 지우기 때문에 **Redis가 초기화됩니다.**
    이 경우 모든 사용자가 다시 로그인해야 하고, 교사의 주간 지급 한도와 학생의 하루 획득 포인트 집계도 처음부터 다시 셉니다.
    학기 중에는 `down`보다 `stop` / `restart`를 사용하세요. ([Redis 데이터가 유지되는 경우](#redis-데이터가-유지되는-경우) 참고)
</Callout>

### Redis 데이터가 유지되는 경우

`redis` 컨테이너에는 데이터 볼륨이 연결되어 있지 않습니다. Valkey는 정상 종료될 때 데이터를 컨테이너 안(`/data`)에 저장하므로, **컨테이너가 그대로 남아 있으면 데이터가 유지되고 컨테이너가 새로 만들어지면 초기화됩니다.**

| 명령 · 상황 | Redis 데이터 |
| --- | --- |
| `docker compose stop` / `start` | 유지 |
| `docker compose restart` | 유지 |
| 서버 재부팅 (Docker가 정상 종료된 경우) | 유지 |
| `docker compose down` 후 `up -d` | **초기화** |
| `docker compose pull`로 새 Valkey 이미지를 받은 뒤 `up -d` | **초기화** |
| `docker-compose.yml`의 `redis` 설정을 바꾼 뒤 `up -d` | **초기화** |
| 정전 등으로 강제 종료된 경우 | 마지막 저장 시점 이후의 변경 사항 손실 |

초기화되어도 데이터베이스(MySQL)의 데이터는 그대로이며, 캐시는 자동으로 다시 만들어집니다.

<Callout type="error">
    `data/` 폴더를 지우면 모든 사용자와 포인트 기록이 사라집니다. 지우기 전에 반드시 [백업](/docs/getting-started/update#백업)하세요.
</Callout>

## 상태 확인

### 실행 상태 보기

```bash
docker compose ps
```

| `STATUS` | 의미 |
| --- | --- |
| `Up` | 실행 중 |
| `Up (healthy)` | 실행 중이며 상태 검사 통과 (`database`, `redis`) |
| `Up (health: starting)` | 시작하는 중 |
| `Restarting` | 오류로 계속 다시 시작되는 중. [로그](#로그-확인)를 확인하세요. |
| `Exited` | 멈춤 |

목록에 서비스가 없으면 컨테이너가 만들어지지 않은 것이므로 `docker compose up -d`를 실행합니다.

### 자원 사용량 보기

```bash
docker stats
```

컨테이너별 CPU, 메모리 사용량을 실시간으로 보여줍니다. `Ctrl + C`로 빠져나옵니다.

## 로그 확인

### 컨테이너 로그

```bash
# 실시간으로 보기 (Ctrl + C로 빠져나오기)
docker compose logs -f server

# 최근 100줄만 보기
docker compose logs --tail 100 server

# 최근 1시간 로그만 보기
docker compose logs --since 1h server
```

서비스 이름을 빼면 모든 서비스의 로그를 함께 보여줍니다.

### 서버 로그 파일

`server`의 로그는 `logs/` 폴더에도 파일로 저장됩니다. 컨테이너를 지워도 남아 있으므로, 지난 기록을 찾을 때는 이 파일을 확인합니다.

| 파일 | 내용 |
| --- | --- |
| `server.log` | API 서버(uvicorn) 실행과 요청 기록 |
| `service.log` | 포인트, 게시글, 퀘스트, 노래방 등 기능별 처리 기록 |
| `database.log` | 데이터베이스 연결과 경고·오류 |
| `redis.log` | Redis 연결과 처리 |
| `global.log` | 서버 시작·종료, 처리되지 않은 오류 |

- 매일 자정에 새 파일로 바뀌며, 지난 로그는 **30일** 동안 보관됩니다.

```bash
# 실시간으로 보기
tail -f logs/service.log

# 오류만 찾기
grep "ERROR" logs/server.log
```

## 설정 변경 적용하기

`.env`나 `docker-compose.yml`을 수정한 뒤에는 `restart`가 아니라 `up -d`로 적용합니다.

```bash
docker compose up -d
```

설정이 바뀐 컨테이너만 새로 만들어집니다. 사용할 수 있는 설정은 [환경 변수](/docs/getting-started/environment)를 참고하세요.

## 업데이트와 백업

```bash
# 업데이트
docker compose pull
docker compose up -d
```

업데이트 전에는 반드시 백업을 해 두세요. 백업과 복원, 특정 버전으로 되돌리는 방법은 [업데이트](/docs/getting-started/update) 문서를 참고하세요.

### 사용하지 않는 이미지 정리

업데이트를 반복하면 예전 이미지가 쌓여 디스크를 차지합니다.

```bash
docker image prune
```

실행 중인 컨테이너가 사용하지 않는 이미지만 지웁니다.

## 컨테이너 안에서 작업하기

### 사용자 · 포인트 관리

관리자 페이지 없이 사용자 추가, 비밀번호 초기화, 포인트 지급 등을 할 수 있습니다. 자세한 사용법은 [CLI 관리 도구](/docs/manage/cli)를 참고하세요.

```bash
docker compose exec server uv run python tools/cli.py --help
```

### MySQL 접속하기

```bash
docker compose exec database sh -c 'mysql -u root -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"'
```

`exit`로 빠져나옵니다.

<Callout type="warning">
    데이터베이스를 직접 수정하면 캐시와 값이 어긋날 수 있습니다. 가능하면 관리자 페이지나 [CLI 관리 도구](/docs/manage/cli)를 사용하세요.
</Callout>

### Redis 접속하기

```bash
docker compose exec redis valkey-cli
```

`exit`로 빠져나옵니다. 저장된 Key를 확인하거나 지울 때는 [CLI 관리 도구의 Redis 명령](/docs/manage/cli#redis)을 사용하는 것이 안전합니다.

### 컨테이너 셸 열기

```bash
docker compose exec server sh
```

컨테이너 안의 파일을 직접 확인해야 할 때 사용합니다. `exit`로 빠져나옵니다.
