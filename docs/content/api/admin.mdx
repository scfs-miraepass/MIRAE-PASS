# 관리자

유저를 만들고, 수정하고, 삭제하는 관리자용 API입니다. 모든 API에 **`MANAGE_USER`** 권한이 필요합니다.

| 방법 | 경로 | 설명 |
| --- | --- | --- |
| `GET` | `/admin/users` | [사용자 목록](#사용자-목록) |
| `POST` | `/admin/user` | [사용자 생성](#사용자-생성) |
| `PATCH` | `/admin/users/{user_id}` | [사용자 정보 수정](#사용자-정보-수정) |
| `PATCH` | `/admin/users/{user_id}/password` | [비밀번호 초기화](#비밀번호-초기화) |
| `DELETE` | `/admin/users/{user_id}` | [사용자 삭제](#사용자-삭제) |
| `POST` | `/admin/point` | [포인트 일괄 처리](#포인트-일괄-처리) |

<Callout type="info">
    많은 유저를 한꺼번에 등록할 때는 API 대신 서버의 명령어 도구를 사용하는 것이 편리합니다. [사용자 관리](/docs/manage/users) 문서를 참고합니다.
</Callout>

## 사용자 목록

`GET /admin/users` · SDK `getUsersAdminUsersGet`

전체 유저 목록을 가져옵니다. 응답 헤더 `X-MAX-PAGE`에 전체 페이지 수가 들어 있습니다.

| 위치 | 이름 | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- | --- |
| 쿼리 | `page` | 숫자 | 1 | 페이지 번호 (1부터 시작) |
| 쿼리 | `size` | 숫자 | 20 | 한 페이지의 유저 수 (1~100) |
| 쿼리 | `user_type` | `student` \| `teacher` \| `service` | | 특정 종류의 유저만 가져옵니다. |
| 쿼리 | `permission` | 숫자 | | 이 [권한](/api/permissions)을 **모두 가진** 유저만 가져옵니다. |

**응답** `200` — [유저 정보](/api/auth#로그인) 목록을 돌려줍니다.

```ts
import { UserPermission } from "@miraepass/api-client"

// 포인트를 지급할 수 있는 교사만 가져오기
const req = await $API.getUsersAdminUsersGet({
    query: { user_type: "teacher", permission: UserPermission.GRANT_POINT, page: 1 },
})
```

## 사용자 생성

`POST /admin/user` · SDK `createUserAdminUserPost`

유저 한 명을 만듭니다. 만들어진 유저는 **비밀번호가 없는 상태**이며, 처음 로그인할 때 직접 비밀번호를 정합니다.

| 위치 | 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- | --- |
| 본문 | `name` | 문자 | ○ | 이름 |
| 본문 | `user_type` | `student` \| `teacher` \| `service` | ○ | 유저 종류 |
| 본문 | `grade` | 숫자 | 학생만 ○ | 학년 |
| 본문 | `number` | 숫자 | 학생만 ○ | 반 |
| 본문 | `student_no` | 숫자 | 학생만 ○ | 번호 |

유저의 ID는 다음 규칙으로 자동으로 정해집니다.

| 종류 | ID 규칙 | 예시 |
| --- | --- | --- |
| 학생 | 학년 + 반 + 번호(두 자리) | 2학년 3반 7번 → `2307` |
| 교사 | 4000부터 비어 있는 가장 작은 번호 | `4000`, `4001`, ... |
| 서비스 | 5000부터 비어 있는 가장 작은 번호 | `5000`, `5001`, ... |

**응답** `201` — 만들어진 유저 정보를 돌려줍니다.

| 오류 | 이유 |
| --- | --- |
| `400` | 학생인데 학년, 반, 번호 중 하나가 빠졌습니다. |
| `409` | 같은 학번의 학생이 이미 있습니다. |

```ts
const req = await $API.createUserAdminUserPost({
    body: { name: "홍길동", user_type: "student", grade: 2, number: 3, student_no: 7 },
})
console.log(req.data?.data.id) // 2307
```

<Callout type="warning">
    API로 만든 유저는 **권한이 하나도 없는 상태(`0`)** 로 만들어집니다.
    만든 직후 [사용자 정보 수정](#사용자-정보-수정)으로 `UserPermission.STUDENT`, `UserPermission.TEACHER` 같은 권한을 꼭 설정해야 합니다.
</Callout>

## 사용자 정보 수정

`PATCH /admin/users/{user_id}` · SDK `updateUserAdminUsersUserIdPatch`

유저의 이름이나 권한을 바꿉니다. **바꾸고 싶은 값만** 보내면 됩니다.

| 위치 | 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- | --- |
| 경로 | `user_id` | 숫자 | ○ | 수정할 유저의 ID |
| 본문 | `name` | 문자 | | 새 이름 |
| 본문 | `permissions` | 숫자 | | 새 [권한](/api/permissions) 숫자. 기존 권한을 **통째로 바꿉니다.** |

**응답** `200` — 수정된 유저 정보를 돌려줍니다.

| 오류 | 이유 |
| --- | --- |
| `400` | 잘못된 값을 보냈습니다. |
| `404` | 유저가 없습니다. |

권한은 **덮어쓰기** 방식이므로, 권한 하나를 추가하려면 기존 권한에 `|`로 더해서 보내야 합니다.

```ts
import { UserPermission } from "@miraepass/api-client"

// 학생 기본 권한 설정
await $API.updateUserAdminUsersUserIdPatch({
    path: { user_id: 2307 },
    body: { permissions: UserPermission.STUDENT },
})

// 기존 권한에 스탬프 발급 권한 추가
await $API.updateUserAdminUsersUserIdPatch({
    path: { user_id: 4001 },
    body: { permissions: user.permissions | UserPermission.GIVE_STAMP },
})
```

## 비밀번호 초기화

`PATCH /admin/users/{user_id}/password` · SDK `resetUserPasswordAdminUsersUserIdPasswordPatch`

유저가 비밀번호를 잊어버렸을 때 사용합니다. 비밀번호를 **없는 상태**로 되돌리며, 유저는 다음 로그인 때 [첫 비밀번호 설정](/api/auth#첫-비밀번호-설정)을 다시 하게 됩니다.
초기화하면 그 유저는 **모든 기기에서 로그아웃**됩니다.

**응답** `204` — 본문이 없습니다. 유저가 없으면 `404`로 응답합니다.

```ts
await $API.resetUserPasswordAdminUsersUserIdPasswordPatch({ path: { user_id: 2307 } })
```

## 사용자 삭제

`DELETE /admin/users/{user_id}` · SDK `deleteUserAdminUsersUserIdDelete`

유저를 삭제합니다. 그 유저의 포인트 기록, 스탬프 등 관련 데이터도 **함께 삭제되며 되돌릴 수 없습니다.**

**응답** `204` — 본문이 없습니다. 유저가 없으면 `404`로 응답합니다.

## 포인트 일괄 처리

`POST /admin/point` · SDK `updateUsersPointAdminPointPost`

여러 유저의 포인트를 **한 번에** 지급하거나 차감합니다. 행사 참가자 전원에게 포인트를 줄 때 등에 사용합니다.

| 위치 | 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- | --- |
| 본문 | `user_ids` | 숫자 목록 | ○ | 대상 유저 ID 목록 |
| 본문 | `amount` | 숫자 | ○ | 바꿀 포인트. **양수이면 지급, 음수이면 차감**합니다. |
| 본문 | `reason` | 문자 | ○ | 이유. 각 유저의 포인트 기록에 남습니다. |

**응답** `204` — 본문이 없습니다.

| 오류 | 이유 |
| --- | --- |
| `400` | `user_ids`가 비어 있습니다. |
| `404` | 목록의 유저를 한 명도 찾지 못했습니다. |

```ts
await $API.updateUsersPointAdminPointPost({
    body: { user_ids: [1101, 1102, 1103], amount: 100, reason: "체육대회 참가" },
})
```

<Callout type="warning">
    포인트 일괄 처리는 **지급 한도와 잔액을 검사하지 않습니다.** 차감하면 포인트가 0 아래로 내려갈 수도 있으므로 주의해서 사용해야 합니다.
    목록 중 존재하지 않는 ID는 오류 없이 건너뜁니다.
</Callout>
