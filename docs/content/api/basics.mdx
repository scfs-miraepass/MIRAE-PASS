# 요청과 응답

API를 사용하려면 **요청을 어떻게 보내고, 응답을 어떻게 읽는지** 알아야 합니다.<br />
이 문서는 모든 API에 공통으로 적용되는 규칙을 설명합니다.

## 요청(Request)의 구성

요청은 크게 **방법(Method)**, **경로(Path)**, **보내는 값**으로 이루어집니다.

```http
POST /point/grant HTTP/1.1
Content-Type: application/json

{ "target_user_id": 1101, "amount": 50, "memo": "수업 참여" }
```

위 요청은 "`/point/grant`(포인트 지급) 주소에, **POST** 방법으로, 1101번 학생에게 50점을 주라는 내용을 보낸다"는 뜻입니다.

### 방법(Method)

같은 주소라도 **방법**에 따라 하는 일이 달라지며, 주로 아래 다섯 가지를 사용합니다.

| 방법 | 뜻 | 예시 |
| --- | --- | --- |
| `GET` | 데이터를 **조회**합니다. | 게시글 목록 보기 |
| `POST` | 새로운 것을 **만들거나 실행**합니다. | 게시글 작성, 로그인, 포인트 지급 |
| `PUT` | 데이터를 **통째로 수정**합니다. | 퀘스트 수정, 비밀번호 변경 |
| `PATCH` | 데이터의 **일부만 수정**합니다. | 게시글 제목만 수정 |
| `DELETE` | 데이터를 **삭제**합니다. | 게시글 삭제 |

### 보내는 값의 세 가지 위치

서버에 값을 전달하는 자리는 세 군데가 있습니다.

| 위치 | 모양 | 언제 쓰는가 |
| --- | --- | --- |
| **경로 값 (Path)** | `/posts/12` | 어떤 대상을 가리킬 때 사용합니다. 문서에서는 `/posts/{post_id}`처럼 중괄호로 표시합니다. |
| **쿼리 (Query)** | `/posts?page=2&size=10` | 검색 조건이나 페이지 번호처럼 **선택 사항**을 붙일 때 사용합니다. `?` 뒤에 `이름=값`을 `&`로 이어 붙입니다. |
| **본문 (Body)** | `{ "title": "공지" }` | 저장할 내용처럼 **많은 데이터**를 보낼 때 사용하며, JSON 형식으로 보냅니다. |

<Callout type="info">
    **JSON**은 데이터를 `{ "이름": 값 }` 모양으로 적는 형식입니다. 사람도 읽기 쉽고 프로그램도 다루기 쉬워 API에서 가장 많이 쓰입니다.
</Callout>

## 응답(Response)의 구성

서버는 요청을 처리한 뒤 **상태 코드**와 **응답 본문**을 돌려줍니다.

### 성공했을 때

미래패스의 API는 성공하면 대부분 아래 모양으로 응답합니다.

```json
{
    "success": true,
    "data": { "id": 1101, "name": "홍길동", "point": 120 }
}
```

- `success`: 성공 여부이며, 성공하면 `true`입니다.
- `data`: 실제로 요청한 데이터가 들어 있습니다. API마다 모양이 다릅니다.

<Callout type="warning">
    상태 코드가 **204 (No Content)** 인 API는 **응답 본문이 비어 있습니다.** 포인트 지급, 삭제, 로그아웃처럼 "잘 처리되었다"는 사실만 알려주면 되는 API가 여기에 해당합니다.
</Callout>

### 실패했을 때

요청이 실패하면 아래 모양으로 응답하며, `message`에 실패 이유가 들어 있습니다.

```json
{
    "success": false,
    "message": "Permission denied."
}
```

단, 보낸 값의 **형식 자체가 틀린 경우(422)** 에는 FastAPI가 만든 다른 모양으로 응답합니다.
예를 들어 숫자가 와야 할 `id`에 글자를 넣고, 필수 값인 `password`를 빠뜨리면 다음과 같이 응답합니다.

```json
{
    "detail": [
        { "type": "int_parsing", "loc": ["body", "id"], "msg": "Input should be a valid integer, ..." },
        { "type": "missing", "loc": ["body", "password"], "msg": "Field required" }
    ]
}
```

`loc`는 문제가 생긴 위치이며, `["body", "id"]`는 "본문의 `id` 값"을 뜻합니다.

## 상태 코드

**상태 코드**는 응답에 붙는 세 자리 숫자로, 결과를 한눈에 알려줍니다. 앞자리가 `2`이면 성공, `4`이면 요청한 쪽의 문제, `5`이면 서버의 문제입니다.

| 코드 | 이름 | 미래패스에서의 의미 |
| --- | --- | --- |
| `200` | OK | 성공했으며, 응답 본문에 데이터가 있습니다. |
| `201` | Created | 새로 만드는 데 성공했습니다. (게시글 작성, 퀘스트 생성 등) |
| `204` | No Content | 성공했으며, 응답 본문은 비어 있습니다. |
| `400` | Bad Request | 규칙에 맞지 않는 요청입니다. (기존 비밀번호 불일치, 포인트 부족, 경매가 진행 중이 아님 등) |
| `401` | Unauthorized | **로그인이 필요합니다.** 로그인하지 않았거나 로그인이 만료되었습니다. |
| `402` | Payment Required | 노래방 입찰에 필요한 포인트가 부족합니다. |
| `403` | Forbidden | 로그인은 했지만 **권한이 없습니다.** |
| `404` | Not Found | 요청한 대상(유저, 게시글, 퀘스트 등)이 없습니다. |
| `409` | Conflict | 이미 존재하는 데이터와 겹칩니다. (이미 받은 스탬프, 중복 학번 등) |
| `422` | Unprocessable Entity | 보낸 값의 형식이 틀렸습니다. (숫자 자리에 글자, 필수 값 누락 등) |
| `429` | Too Many Requests | 한도를 넘었습니다. (주간 포인트 지급 한도, 퀘스트 반복 횟수 등) |
| `500` | Internal Server Error | 서버 내부에서 예상하지 못한 오류가 발생했습니다. |
<Callout type="info">
    모든 상태 코드는 [공식 문서](https://developer.mozilla.org/ko/docs/Web/HTTP/Reference/Status)에서 확인할 수 있습니다.
</Callout>

## 로그인과 쿠키

대부분의 API는 **로그인한 사람만** 사용할 수 있습니다. 미래패스는 **세션 쿠키** 방식으로 로그인 상태를 기억합니다.

<Steps>

### 로그인 요청

`POST /auth/login`으로 아이디(학번)와 비밀번호를 보냅니다.

### 서버가 쿠키를 발급

로그인에 성공하면 서버는 `session_id`라는 **쿠키**를 응답에 담아 보냅니다.
쿠키는 브라우저가 보관하는 작은 메모이며, 일종의 **입장 팔찌**라고 생각하면 됩니다.

### 이후 요청에 쿠키가 자동으로 포함

브라우저는 같은 서버로 요청할 때마다 이 쿠키를 **자동으로** 함께 보냅니다.
서버는 쿠키를 보고 "1101번 학생의 요청이구나"라고 판단합니다.

### 로그아웃 또는 만료

`POST /auth/logout`을 호출하거나 **7일** 동안 사용하지 않으면 쿠키가 더 이상 유효하지 않으며, 이때부터는 `401` 오류가 발생합니다.

</Steps>

<Callout type="info">
    - 쿠키는 `HttpOnly`로 설정되어 있어 **JavaScript 코드로는 읽을 수 없습니다.** 해킹 프로그램이 쿠키를 훔쳐 가지 못하게 막기 위한 장치입니다.
    - `GET /auth`를 호출할 때 남은 기간이 절반(3.5일) 미만이면 **기간이 자동으로 다시 7일로 연장**됩니다.
    - 비밀번호를 바꾸거나 관리자가 비밀번호를 초기화하면, 그 유저의 **모든 기기에서 로그아웃**됩니다.
    - 개발 환경(HTTP)에서는 서버 `.env`에 `DEBUG=true`를 설정해야 쿠키가 유지됩니다.
</Callout>

## 응답 헤더

**헤더(Header)** 는 응답 본문과 별도로 붙어 오는 추가 정보입니다. 미래패스는 다음 헤더를 사용합니다.

| 헤더 | 뜻 | 붙는 API |
| --- | --- | --- |
| `X-Server-Version` | 서버 버전입니다. (예: `1.14.1`) | 모든 API |
| `X-MAX-PAGE` | 전체 페이지 수입니다. 목록의 마지막 페이지를 계산할 때 사용합니다. | 목록 조회 API |
| `X-CACHED` | `true`이면 Redis에 저장해 둔 결과를 그대로 돌려준 것입니다. | 일부 목록 조회 API |

## 목록 나누어 받기 (페이지네이션)

데이터가 수천 개일 때 한 번에 모두 받으면 느리기 때문에, 목록 API는 **조금씩 나누어** 받습니다. 이를 **페이지네이션**이라고 합니다.
미래패스에는 두 가지 방식이 있으며, API마다 사용하는 방식이 다릅니다.

| 방식 | 쿼리 | 예시 | 사용하는 API |
| --- | --- | --- | --- |
| **limit / offset** | `limit`: 가져올 개수<br />`offset`: 건너뛸 개수 | `?limit=20&offset=40` → 41번째부터 20개 | 포인트 기록, 랭킹, 퀘스트, 노래방 |
| **page / size** | `page`: 페이지 번호(1부터)<br />`size`: 한 페이지의 개수 | `?page=3&size=20` → 3페이지(41~60번째) | 게시글, 관리자 유저 목록 |

한 번에 가져올 수 있는 개수는 최대 **100개**이며, 별도로 적지 않으면 **20개**를 가져옵니다.

## 날짜와 시간

날짜와 시간은 **ISO 8601** 형식의 문자열로 주고받습니다.

```text
2026-11-04T13:30:00+09:00
└─ 날짜 ─┘ └ 시간 ┘ └ 시간대 ┘
```

마지막의 `+09:00`은 한국 시간(KST)이라는 뜻입니다. 시간을 보낼 때도 시간대를 함께 적는 것이 안전합니다.
