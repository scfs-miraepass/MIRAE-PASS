# 권한

미래패스에는 학생, 교사, 매점·카페 같은 서비스 계정, 관리자가 함께 사용합니다.<br />
학생이 다른 학생에게 마음대로 포인트를 줄 수 있으면 안 되므로, **누가 무엇을 할 수 있는지** 정해 두어야 하며 이것이 **권한**입니다.

## 유저 종류

| 종류 (`type`) | 설명 | ID 규칙 |
| --- | --- | --- |
| `student` | 학생 | 학번을 그대로 사용합니다. (예: 1학년 1반 1번 → `1101`) |
| `teacher` | 교사 | `4000`번부터 순서대로 만들어집니다. |
| `service` | 매점, 카페 등 포인트를 차감하는 계정 | `5000`번부터 순서대로 만들어집니다. |

## 권한은 숫자 하나로 저장됩니다

권한 정보는 유저의 `permissions` 값에 **숫자 하나**로 저장됩니다. 여러 개의 권한을 숫자 하나에 담는 방법은 **전등 스위치판**을 떠올리면 이해하기 쉽습니다.

```text
스위치 번호:  ... 6  5  4  3  2  1  0
켜짐 여부:    ...  1  0  0  0  0  1  0   ← 1번 스위치(포인트 지급)와 6번 스위치(랭킹 보기)가 켜짐
```

각 권한은 **스위치 하나**이며, 켜진 스위치를 2진수로 읽은 값이 `permissions` 숫자가 됩니다.
위의 예시는 2진수 `1000010`이므로, 10진수로 `64 + 2 = 66`이 됩니다.
이런 방식을 **비트 플래그(Bit Flag)** 라고 하며, 숫자 하나만 저장하면 되어 효율적입니다.

<Callout type="info">
    권한을 직접 계산할 필요는 없습니다. SDK가 제공하는 `UserPermission` 값을 더하거나(`|`) 확인(`&`)하면 됩니다.
    자세한 방법은 [SDK 사용하기 - 권한 확인하기](/api/sdk#권한-확인하기)를 참고합니다.
</Callout>

## 권한 목록

| 이름 | 값 | 설명 |
| --- | --- | --- |
| `DEDUCT_POINT` | 2⁰ + 검색 | 다른 유저의 포인트를 **차감**합니다. (매점·카페) |
| `GRANT_POINT` | 2¹ + 검색 | 다른 유저에게 포인트를 **지급**합니다. |
| `NO_LIMIT_POINT` | 2² | 주간 지급 한도 없이 포인트를 지급합니다. 이 권한을 가진 교사는 **랭킹에 표시되지 않습니다.** |
| `CREATE_QUEST` | 2³ | 퀘스트를 만듭니다. |
| `MANAGE_QUEST` | 2⁴ | 다른 사람이 만든 퀘스트도 수정·삭제합니다. |
| `GIVE_STAMP` | 2⁵ + 검색 | 다른 유저에게 스탬프를 발급합니다. |
| `VIEW_RANK` | 2⁶ | 포인트 랭킹을 봅니다. |
| `VIEW_POINT` | 2⁷ | 자신의 포인트를 봅니다. |
| `VIEW_POINT_HISTORY` | 2⁸ | 자신의 포인트 기록을 봅니다. |
| `MANAGE_POST` | 2⁹ | 다른 사람이 쓴 게시글도 수정·삭제합니다. |
| `CREATE_POST` | 2¹⁰ | 게시글을 작성합니다. |
| `VIEW_USER_POINT` | 2¹¹ + 검색 | **다른 유저**의 포인트를 봅니다. |
| `JOIN_QUEST` | 2¹² | 퀘스트에 참여해 완료합니다. |
| `MANAGE_USER` | 2¹³ + 검색 | 유저 생성·수정·삭제, 비밀번호 초기화, 포인트 일괄 처리를 합니다. |
| `VIEW_POST` | 2¹⁴ | 게시글을 봅니다. |
| `VIEW_STAMP` | 2¹⁵ | 자신의 스탬프를 봅니다. |
| `VIEW_QUEST` | 2¹⁶ | 퀘스트를 봅니다. |
| `SEARCH_USER` | 2¹⁷ | 유저를 이름이나 학번으로 검색합니다. |
| `JOIN_KARAOKE` | 2¹⁸ + 검색 | 노래방 경매에 참여합니다. (파티 생성, 초대, 입찰) |
| `MANAGE_KARAOKE` | 2¹⁹ | 노래방 경매를 만들고 삭제합니다. |
| `VIEW_KARAOKE` | 2²⁰ | 노래방 경매를 봅니다. |

**"+ 검색"** 이 붙은 권한은 `SEARCH_USER` 권한을 **자동으로 함께 포함**합니다.
포인트를 지급하려면 먼저 대상 학생을 검색해야 하기 때문입니다.

<Callout type="warning">
    `_GRANT_POINT`처럼 이름 앞에 밑줄(`_`)이 붙은 값은 "검색 권한을 뺀 순수한 스위치 하나"를 뜻하며, 내부 계산용입니다.
    일반적으로는 밑줄이 없는 이름을 사용합니다.
</Callout>

## 미리 묶어 둔 권한

자주 쓰는 조합은 미리 묶어 두었습니다.

| 묶음 | 포함된 권한 |
| --- | --- |
| `STUDENT` | 랭킹 보기, 포인트 보기, 포인트 기록 보기, 게시글 보기, 노래방 보기·참여 |
| `TEACHER` | 포인트 지급, 랭킹 보기, 포인트 보기, 포인트 기록 보기, 다른 유저 포인트 보기, 게시글 보기, 스탬프 보기, 노래방 보기·참여 |
| `ADMIN` | 유저 관리, 게시글 관리·작성, 퀘스트 관리, 노래방 관리·보기 |

권한은 관리자가 [사용자 정보 수정](/api/admin#사용자-정보-수정) API로 바꿀 수 있습니다.

## 권한이 없으면

권한이 없는 API를 호출하면 서버는 **`403 Forbidden`** 으로 응답합니다.

```json
{ "success": false, "message": "Permission denied." }
```

화면에서도 버튼을 숨기는 등 미리 막아 두는 것이 좋지만, **최종 판단은 항상 서버가 합니다.**
화면에서 버튼을 숨기는 것만으로는 보안이 되지 않습니다. 누구나 개발자 도구로 직접 요청을 보낼 수 있기 때문입니다.
